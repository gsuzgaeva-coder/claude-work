# Подключение источника данных

Один источник за раз, до сверки с первоисточником. Образец готового источника —
Яндекс Маркет (`scripts/ym_supplies_export.py`, скилл `ym-priemki`).

## Шаги

1. **Понять, что отдаёт источник.** Попроси у логиста реальную выгрузку (файл в
   `data/входящие/` или в чат) или документацию к API. Выясните: какие там поля, есть ли баркод, есть ли номер документа, чем
   различаются «заявлено», «отгружено», «принято», за какой период доступна история.
   Не предполагай формат по названию колонки — посмотри на 10–20 живых строк.
   UPSELLER и UPMARKET отдают данные и по API, и файлом: если документации к API
   нет или она непонятна, начни с файла.
2. **Выбрать способ получения**, от надёжного к ручному:
   API площадки/фулфилмента → регулярная выгрузка файла в папку `data/входящие/` →
   ручная вставка. Автоматический способ лучше, но рабочая ручная выгрузка сегодня
   полезнее автоматической через месяц. Начните с файла, автоматизируйте потом.
3. **Определить «что считать фактом».** Запишите правило отбора словами в
   `knowledge/` (как сделано для ЯМ): какие типы и статусы документов входят, какие
   нет и почему. Спорные случаи решает логист.
4. **Написать загрузчик** в `scripts/` по образцу ЯМ: читает источник → приводит к
   полям журнала → сопоставляет с баркодом по справочнику → проверяет сам себя →
   пишет файл для загрузки. Ключи — только из `.env`.
5. **Проверить на истории.** Загрузите прошлый период и сверьте итог с тем, что
   показывает сам источник (кабинет, отчёт фулфилмента). Не сходится — ищите причину
   до того, как вносить в журнал.
6. **Загрузить в журнал, записать в «Журнал_загрузок»**, добавить источник на витрину
   с датой обновления.
7. **Описать** в `knowledge/` и в `ЖУРНАЛ_ПРОЕКТА.md`: откуда берём, как часто, кто
   отвечает, что делать, если источник не обновился.

## Ключи и доступы

Попроси логиста получить ключ в кабинете (нужны права только на чтение, если
площадка это позволяет) и вписать его в `.env` — строки для ключа добавь в `.env` и
`.env.example` сам, с подсказкой, где ключ взять. Не проси присылать ключ в чат.
Проверь, что `.env` указан в `.gitignore`.

## На что смотреть у каждого типа источника

- **Остатки фулфилмента** — это снимок на момент, а не журнал: храните дату снимка,
  различайте «всего», «доступно к отгрузке», «в резерве/собрано под заявку», «брак».
  Отгружать можно только «доступно».
- **Отгрузки фулфилмента** — нужен номер поставки площадки в каждой строке, иначе не
  сверить с приёмкой. Если фулфилмент его не пишет — договориться, чтобы писал.
- **Приёмки площадки** — у каждой свои понятия (на WB — поставки и приёмка по
  складам, на Ozon — заявки на поставку, на Lamoda — приходные накладные). Везде
  ищите одно и то же: номер документа, дата приёмки, баркод, заявлено, принято.
- **Приходы партий** — источник обычно бумажный или файл поставщика. Сверяйте
  количество по накладной с приёмкой фулфилмента: расхождение — отдельная строка.
