# Резервные копии и защита

## Резервная копия

Копия — это вся книга целиком одним файлом `.xlsx` (включая скрытые листы) в папке
`backups/<дата_время>.xlsx`. Скрипт копирования напишите вместе с логистом, когда
появится сама система и станет понятно, где она живёт: для Google Таблицы — выгрузка
книги через сервисный аккаунт компании (ключ — в `.env`), для базы данных — её дамп.
Пока скрипта нет, копию делает логист вручную: Файл → Скачать → Microsoft Excel.

Когда делать: каждый рабочий день; перед любой правкой больше ~50 строк; перед
изменением структуры или формул; перед тем как дать доступ новому человеку.
Копии храним не меньше 60 дней, копии на конец месяца — бессрочно. Папку `backups/`
держите в облачной папке компании, а не только на одном компьютере.

После скачивания проверьте копию: файл открывается, число листов и строк в главных
журналах совпадает с таблицей. Непроверенная копия — не копия.

## Восстановление

1. Не чините поверх поломки. Сначала сделайте копию текущего (сломанного) состояния —
   по ней потом видно, что именно изменилось.
2. Найдите масштаб: сравните сломанное состояние с последней хорошей копией по листам
   и строкам.
3. Если затронут один лист — верните его из копии. Если непонятно что — история версий
   Google Таблицы (Файл → История версий) покажет, кто и когда менял.
4. Журналы после восстановления сверьте с первоисточниками (скилл `sverka`).
5. Запишите в `ЖУРНАЛ_ПРОЕКТА.md`: что случилось, почему, что изменили, чтобы не
   повторилось.

## Права доступа

| Кто | Что может |
|---|---|
| Аккаунт компании | владелец таблицы |
| Логист | редактор всего |
| Менеджер площадки | просмотр всей книги; правка только своего листа заявок |
| Руководитель | просмотр; правка по желанию |
| Сервисный аккаунт скриптов | редактор (для загрузок и копий) |

- Журналы, расчёты, справочники, витрина — защищённые листы, править может только
  логист и сервисный аккаунт. Выдавать менеджерам «редактора всей таблицы» нельзя:
  защита листов должна оставаться включённой.
- Доступ выдаётся по адресам конкретных людей, не «всем, у кого есть ссылка».
- При уходе сотрудника: убрать его доступ в тот же день, проверить, что ни один
  источник данных и ни одна таблица не принадлежат его аккаунту.
- В рабочей книге не должно быть скрытых строк и скрытых листов с данными: скрытое
  никто не проверяет, а вставка данных при скрытых строках попадает не туда. Служебное
  — на отдельные видимые листы с понятным названием.
- После каждого изменения структуры проверяйте, что защита листов на месте.
